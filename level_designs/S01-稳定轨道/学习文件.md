## 1. 用户要求

- 可以采用较复杂结构，但必须优先保证方向正确、稳定入轨、三轴可控和结构完整。

- 正常火箭必须鼻锥、主油箱在上，发动机、喷口和支脚在下；点火时喷焰朝下，火箭向上。

## 3. 最重要的方向知识

必须区分四件事：建造轴、发动机位置、喷焰方向、火箭受力方向。

1. 工具建造轴：`+Z` 为竖直上方。V1 已通过截图证明 `+Y` 不是竖直轴。
2. 发动机位置：Booster 必须物理位于主油箱和鼻锥下方。V2 虽竖直，但发动机位于顶端，仍然上下颠倒。
3. 喷焰方向：点火后火焰和烟雾必须朝地面向下。
4. 受力方向：火箭的反作用力与喷焰相反；喷焰向下，火箭才应向上。

V3 提供了关键反例：Booster 装在小油箱顶面时，MCP 返回 `Thrust ... straight up`，但实机截图显示喷焰也向上，火箭实际受到向下的反作用力。因此 MCP 的 Booster 朝向文字不能单独作为真实推进验收。今后必须同时记录工具文字、完整几何位置和实机短点火；三者冲突时，以实机喷焰及真实运动为准。

## 6. V4 控制

主文件仅修改原始结构副本中的合法 `Data`，几何和连接不得改变。

| 按键 | 控制部件 |
| --- | --- |
| `↑ / ↓` | 四台 Booster 同步启动 / 关闭；toggle 模式，非自动 |
| `← / →` | 两个竖直轴反作用轮控制偏航 |
| 小键盘 `8 / 2` | 东西侧反作用轮与 RCS 控制俯仰 |
| 小键盘 `4 / 6` | 南北侧反作用轮与 RCS 控制侧倾 |

相反安装面的控制块交换 `bmt-left` / `bmt-right`。反作用轮统一启用自动制动、`speed=2.0`、`damper=1.5`；RCS 启用自动制动。若实机只有某个姿态轴反向，只交换该轴整对键值，不增加几何版本。

## 8. 游戏内验收流程

静态 XML 不能替代以下测试：

1. 加载 V4 主文件，确认鼻头在上、四台 Booster 吊在小燃料舱下方、四个 Grip Pad 接地且发动机不触地。
2. 不点火，短按 `←/→`、小键盘 `8/2`、`4/6`，确认三轴响应与自动制动。
3. 极短按一次 `↑`，必须看到四股喷焰同步朝下；立即按 `↓`。
4. 只有确认火箭向上离地，才做第二次较长点火。若仍向下，保存截图并创建 V5，不要仅改按键。
5. 检查四路 Fuel Line 持续供油；最大推力、急转和落地后不得连锁解体。
6. 用小键盘 `8/2` 转入切向加速，方向键修正偏航，小键盘 `4/6` 消除侧倾。
7. 先完成连续三圈，再缩短有效飞行时间；保存 Tracker 轨迹 CSV。
8. 结束时确认全部 51 个原始块仍连接 Starting Block，并在 Besiege 中保存真实缩略图。

## 9. 新 Agent 接续规则

1. 先读本文件和 V4 使用说明，首选测试 V4；V1、V2、V3 不再作为候选。
2. 只改合法按键、力度或制动参数时保留 V4 版本号，并同步更新说明与本文件。
3. 只要需要移动、翻转、增加、删除或重新连接方块，就保留 V4 并新建 V5 MCP 生命周期。
4. 新火箭仍沿工具 `+Z`，但发动机验收以“喷焰朝下、火箭向上”的实机结果为最终标准。
5. 新文件直接放入 `level_designs/S01-稳定轨道/`，不得建立模型子目录；文件名必须版本开头、时间结尾。
6. 原始结构封存前必须调用 `get_machine_summary`，再保存并关闭生命周期。
7. 完成后更新版本历史、当前候选、静态结果、动态结果和文件索引，保证下一位 Agent 仅凭本文件即可继续。
