# 模型归档与命名规范

## 目录层级

每个赛道先建立一个赛道目录，所有属于该赛道的模型与配套文件直接平铺在此目录内，不再为每个模型套一层版本文件夹。

赛道目录格式：`赛道号-赛道名称`

模型及配套文件的基本格式：`V版本号-模型名称-YYMMDD-HHMMSS.扩展名`

如果需要区分原始结构、使用说明、学习摘要或构建记录，把说明词放在模型名称之后、时间之前，确保时间永远位于文件基本名的最后：`V版本号-模型名称说明词-YYMMDD-HHMMSS.扩展名`

正确示例：

```text
S01-稳定轨道/
├── 学习文件.md
├── V3-底置四发轨道火箭-260905-124510.bsg
├── V3-底置四发轨道火箭原始结构-260905-124510.bsg
├── V3-底置四发轨道火箭使用说明-260905-124510.md
├── V3-底置四发轨道火箭构建记录-260905-124510.json
└── V3-底置四发轨道火箭完整记录-260905-124510.json
```

错误示例：

- `S01-稳定轨道/V3-底置四发轨道火箭-260905-124510/模型.bsg`：多套了一层模型文件夹。
- `底置四发轨道火箭-V3-260905-124510.bsg`：版本号不在最前。
- `V3-底置四发轨道火箭-260905-124510_tuned.bsg`：时间不是最后一段。

## 每个可交付版本应包含

- 主 `.bsg`：已经写入合法控制参数、供日常加载和比赛测试。
- 原始结构 `.bsg`：MCP 封存结果；若主文件与原始结构相同，可省略重复副本。
- MCP 有效构建记录与完整记录，说明词分别用“构建记录”和“完整记录”。
- 使用说明和学习摘要；赛道目录还必须有一份自包含的 `学习文件.md`。
- 真实模型缩略图：只能来自 Besiege 实际载入并保存该模型后生成的缩略图；未取得时留空并标注待补，不能用概念图或其他版本截图替代。

## 固定规则

1. 开始建模前先确定赛道目录；禁止把不同赛道的模型混放在项目根目录。
2. 每次形成可独立加载的新几何设计时版本号加一；只改文档、封面或合法控制 `Data` 不增加几何版本号。
3. 时间采用模型首次生成完成的本地时间，重命名或移动不得篡改。
4. 主模型的 XML 内部 `Machine name` 应与主 `.bsg` 的文件基本名一致；原始结构副本也按自己的文件基本名命名。
5. 同一赛道的历史失败版本保留在赛道目录中，并在 `学习文件.md` 标明失败原因，避免后续重复犯错。
6. 新 Agent 或新工作环境接手时，必须先读赛道目录中的 `学习文件.md`，再决定是继续实测、只改合法参数，还是创建下一几何版本。
