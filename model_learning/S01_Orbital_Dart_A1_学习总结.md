# S01 轨道飞船 Orbital Dart A1：设计与学习总结

> **版本状态：已淘汰。** 实机截图证明本版把工具坐标 `+Y` 错当成游戏竖直轴，导致飞船在场景中横躺。BuildArena 建造工具中的竖直方向应使用 `+Z`。A1 只保留为坐标映射错误样本，后续由沿 `+Z` 竖直建造的 Orbital Lancer V2 取代。

## 赛项定位

- 赛项：BuildArena 2.0 Construction Challenge，Season 01 “Stable Orbital”。
- 参赛路线：`Build with Agent`。
- 构建模式：`Autopilot`。人工只在正式构建开始前给出初始要求；开始后飞船结构全部由 Agent 通过 BuildArena MCP 生成，没有手工修改 BSG 几何。
- 原始机器内部名：`S01_Autopilot_Orbital_Dart_A1_260904_210409`。
- 规则依据：[Construction Challenge](https://build-arena.github.io/ConstructionChallenge/) 与 [Kaggle 赛项页](https://www.kaggle.com/competitions/build-arena-human-ai-colleberation-engineering-challenge/overview)。

S01 的性能分由轨道进度、速度和结构完整性组成，权重分别为 `70% / 20% / 10%`。累计完成三圈可取得满轨道进度；Autopilot 模式最终分乘 `1.15`。因此本版不追求复杂外形，优先保证推力轴对称、姿态可控、起始块始终连接，并把总方块数控制在 17 块。

## A1 结构方案

| 子系统 | 数量 | 设计作用 |
| --- | ---: | --- |
| Starting Block | 1 | 位于尾部轴线原点，是官方轨迹跟踪目标，也是全船受力根节点。 |
| Fuel Barrel Big | 1 | 位于 `[0, 2, 0]`，作为 100 单位主油箱与质量核心。 |
| Booster | 4 | 位于 `y = 4` 的 `x/z = ±0.5` 四角，全部沿北向 `+Y` 推进。 |
| Reaction Steering Block | 3 | 分别绕东西轴、竖直轴和纵向轴提供俯仰、偏航与滚转控制。 |
| Brace | 8 | 四根加固 Starting Block—油箱，四根加固发动机簇—油箱。 |

四台助推器关于纵轴完全对称，名义总推力约等于正常重力下 `96` 个质量单位；大油箱提供 100 单位主燃料，四台助推器还各有 1 单位内部燃料。推进器直接安装在可供油的油箱端面上，不需要额外燃料管，减少了方块数和潜在断点。

三只反作用轮的控制轴互相正交：

- ID 7：东西轴，用于俯仰。
- ID 8：竖直轴，用于偏航。
- ID 9：南北纵轴，用于滚转，并直接连接在 Starting Block 上。

结构上刻意避免分离器、外挂整流罩和纯装饰件。它们会增加成本，也可能在飞行结束时变成与 Starting Block 断开的跟踪块，降低结构完整性。

## 受力与完整性设计

1. Starting Block 与大油箱除中心安装连接外，又通过东、西、上、下四根斜拉杆建立冗余受力路径。即使单个安装连接在大推力下变弱，核心仍不应立即脱离。
2. 四台助推器各有一根独立斜拉杆连接到油箱前肩，发动机推力不会全部集中在四个端面接点上。
3. 四台助推器的推力线合成后穿过油箱中心轴，可降低点火时的被动偏航和俯仰。
4. 油箱是全船最大的质量体，反作用轮围绕油箱中部布置；燃料减少时，质量中心主要沿纵轴变化，不会产生明显左右偏载。

## 原始版与调参版边界

原始 `.bsg` 已由 MCP 保存并封存，当前不能再改几何。BSG 中推进器和反作用轮的 `Data` 均为空，表示使用游戏默认参数；它们还没有完成按键和力度实机调校。

赛项允许在原始机器保存后复制出 `machine_tuned.bsg`，只调整合法的非几何 `Data` 字段、按键、力度和开关方式。建议的调参版控制布局如下：

- `↑`：四台主推进器同步点火；建议使用按住工作，不使用永久锁定。
- 数字小键盘 `8 / 2`：俯仰上 / 下。
- 数字小键盘 `4 / 6`：偏航左 / 右。
- `Q / E`：滚转左 / 右。
- 不配置反向主推进；需要减速时先掉头，再短促点火。

所有力度、速度和控制参数必须保持在原版游戏允许范围内，不能修改位置、旋转、缩放、连接器端点或结构。

## 建议飞行流程

1. 在 The Broken Beyond 太空沙盒加载原始版，先进行一次低油门短点火，确认四台助推器均沿同一方向工作且船体没有自发偏转。
2. 复制并另存为调参版，只修改合法控制参数；让船头对准行星表面的切向方向。
3. 主推进加速到能够持续绕行的切向速度后关闭推进。不要持续径向爬升，否则角速度和有效轨道进度都会变差。
4. 用俯仰和偏航做小幅修正，让轨迹围绕轨道中心连续转动；滚转只用于恢复操纵方向，不用于频繁机动。
5. 以完成三圈为第一目标；三圈完成后再尝试缩短有效飞行时间，以提高速度分。
6. 飞行结束前不要主动分离任何部件，确保 17 个原始跟踪块仍与 Starting Block 连通。

## 必须完成的动态验收

- 四台助推器同时点火，合力方向为 `+Y`，船体没有持续俯仰、偏航或滚转漂移。
- 主油箱能向四台助推器供油，不出现只有个别发动机持续工作的情况。
- 俯仰、偏航、滚转三轴均能从静止姿态恢复，并能在主推进关闭后细调。
- 最大推力短点火后，Starting Block—油箱连接和四台发动机连接均不脱落。
- 官方 Tracker 能输出 Starting Block 的轨迹 CSV；原始 BSG 已配置 `10 Hz` 采样。
- 至少完成一次连续三圈的有效轨道飞行，再以更短用时重复测试。
- 结束时逐项核对 17 个原始块是否仍连接到 Starting Block。

## 本版得到的设计结论

1. 评分中的轨道进度权重最高，飞船首先要稳定完成三圈；单纯增加主推力但无法收敛到连续轨道，不会得到高分。
2. Starting Block 是轨迹与结构完整性的共同核心，不能只靠一个安装接点挂在大油箱后方；围绕它建立四向冗余拉撑的收益高于增加装饰外壳。
3. 对称四发比单发更容易让合力穿过质量中心，也允许单个连接得到独立加固；代价是耗油更快，因此应采用短促入轨点火而不是全程点火。
4. 三只互相正交的反作用轮用很少的方块提供完整三轴姿态控制，适合真空环境；大气舵面在本任务中不是优先部件。
5. 原始版的几何一旦封存就不应再动。后续改进应先通过合法 `Data` 调参和驾驶策略验证，只有结构性问题确实存在时才创建新的 MCP 版本。
